# Web Extract Output

Defines the file shape for materializing extracted web content as markdown. Pure format contract — does not decide *where* the file lands.

## Frontmatter (always at top)

Shared across all types:

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `title` | text | yes | From source metadata; never invent |
| `source` | url | yes | Original URL passed to web-x |
| `type` | text | yes | `article` \| `transcript` \| `crawl` |
| `created` | date | yes | ISO `YYYY-MM-DD` — date file was generated |
| `author` | text | no | Omit if unknown — never fabricate |
| `published` | date | no | ISO date of original publication/upload |
| `tags` | list | yes | `[]` if none |

Per-type additions:

- **article** → `domain` (URL hostname)
- **transcript** → `platform` (youtube/vimeo/tiktok/twitter/twitch/soundcloud/other), `channel`, `duration` (e.g. `1:23:45`), `views` (number)
- **crawl** → `page_count` (number), `crawled_at` (ISO datetime)

## Filename

kebab-case slug of `title`, `.md` extension:

- lowercase, ASCII only (transliterate diacritics, drop non-Latin scripts)
- non-alphanumeric → `-`, collapse consecutive `-`, trim ends
- max 60 chars, cut at word boundary
- on collision: append `-2`, `-3`, …
- if slug is empty after stripping → `<domain>-<created>.md`

## Body

- **No H1.** Title lives in frontmatter; Obsidian's reading view shows it from there.
- Strip extraction-tool separators (`=== METADATA ===`, `=== TRANSCRIPT ===`) — that data moves to frontmatter or per-type sections below.
- Preserve all original markdown — links, images, lists, code blocks, tables.
- External URLs as bare `[text](url)` — no wikilinks for external content.
- Trim trailing whitespace; collapse ≥3 blank lines to 2; one trailing newline at EOF.

### Per-type body

**article** — body is the cleaned extraction directly. If a leading H1 duplicates the frontmatter title, drop it.

**transcript** — if the source description is non-empty:

```
## Description

<description>

## Transcript

<plaintext transcript>
```

Else just `## Transcript` followed by the text.

**crawl** — each page as:

```
## <Page Title>

<page URL>

<page markdown>
```

For ≥20 pages, optionally prepend a `## Pages` section with in-file links (`[[#<page title>]]`).

## Don't

- ❌ No "Source: …" or "Extracted on …" line in body — that data is in frontmatter.
- ❌ No "Generated by …" footer.
- ❌ Don't auto-tag from content sniffing — leave `tags: []` unless the source provides explicit tags.
- ❌ Don't summarize, translate, or truncate the body — verbatim only.
- ❌ Don't fabricate `author`, `published`, or any field absent from the source.

## Examples

### Article

```markdown
---
title: How to Do Great Work
source: https://paulgraham.com/greatwork.html
type: article
created: 2026-06-08
author: Paul Graham
published: 2023-07-01
domain: paulgraham.com
tags: []
---

If you collected lists of techniques for doing great work in all different fields, what would the intersection look like? ...
```

### Transcript

```markdown
---
title: Stewart Brand on the Long Now
source: https://www.youtube.com/watch?v=abc123
type: transcript
created: 2026-06-08
published: 2024-03-15
platform: youtube
channel: Long Now Foundation
duration: 1:23:45
views: 142000
tags: []
---

## Description

Stewart Brand discusses long-term thinking and the 10,000 year clock.

## Transcript

so the question we asked ourselves was what would it look like to build a clock that could last ten thousand years ...
```

### Crawl

```markdown
---
title: Example Docs
source: https://docs.example.com
type: crawl
created: 2026-06-08
page_count: 12
crawled_at: 2026-06-08T14:32:00
tags: []
---

## Getting Started

https://docs.example.com/start

<page markdown>

## Configuration

https://docs.example.com/config

<page markdown>
```
